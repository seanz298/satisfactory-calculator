# 跨方案实时连接验收

基于 main `7144272` 的独立开发分支。没有合并或部署 main。

## 自动回归

运行 `tests/` 下的计算测试（不含 `browser-live-links.cjs` 和夹具生成器）。其中：

- `live-plan-links.cjs`：有限分配、来源变更、循环回滚、存储往返、删除当前来源、旧草稿恢复和导入身份映射。
- `live-link-modes.cjs`：不足继续生产、反推与单输入约束、原矿实时上限、多级依赖失败、重复连接和供给锁定。
- `plan-network.cjs`：共享产能、循环、失效引用、不修改输入。
- `live-link-ui.cjs`：拖线事件处理；此项本身不验证浏览器布局。
- 其余既有测试覆盖回收优化器、配方场景、原矿反推、手动连接、流体处理、回流、机器排序、导入和不可行诊断。

## 实际浏览器验收

Chromium 桌面浏览器，使用应用界面、键盘和实际鼠标拖动完成。未通过执行页面脚本注入连接。

| 操作 | 观察结果 |
| --- | --- |
| 将来源铁锭端口拖到接收方案卡片 | 出现连接与申请量 100，接收方案可行 |
| 来源 100，同时向两个接收方案各申请 100 | 分配 50 / 50，需求超过额度的方案不可行 |
| 将申请改为 60 / 40 | 分配 60 / 40，无缺口，两方案可行 |
| 通过表单尝试接收方反向供给来源 | 显示循环依赖，原连接保留 |
| 切换到来源，将产量从 100 改为 50 | 接收方立即变为 30 / 20，显示相应缺口 |
| 刷新页面后打开连接图 | 来源 50、两个申请和分配 30 / 20 保留 |
| 删除正在编辑的命名来源 | 两个接收方显示来源缺失，不再由当前草稿供货 |
| 撤销删除 | 来源身份、连接和分配恢复 |
| 断开接收一的连接 | 恢复原手填供给 80，接收一可行；接收二额度恢复 40 |
| 中英文切换 | 新面板、分配表和动作文本翻译；自定义方案名称保留 |

未运行 Playwright 独立脚本 `browser-live-links.cjs`，也未实测 Firefox、Safari 或移动触摸拖线。桌面实测不代表这些平台已验收。浏览器扩展记录了元数据发送错误，未观察到应用脚本错误。

## 复现夹具

1. `python3 scripts/build.py`
2. `node tests/make-browser-fixture.cjs`
3. 在一次性本地测试站点中打开 `dist/live-links-acceptance.html`。页面首次打开会写入三份测试方案；刷新保留测试编辑。请使用独立浏览器环境，避免覆盖真实工作台数据。
4. 按上表操作。夹具在 `dist/`，不进入根目录网页或发布内容。单文件根页面仍是 `index.html`。

夹具初始化标记存在当前标签页 sessionStorage 中；重新运行生成器只更新页面代码，不重置该标签页的测试状态。
