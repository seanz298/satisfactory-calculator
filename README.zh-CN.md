# 幸福工厂产线计算器

[English](README.md) | **简体中文**

面向《Satisfactory》1.2 的中英双语产线规划工具。可以从手头的资源出发，也可以从想要的产物反推，算出机器台数、频率、物料流量、电力和副产物，再用交互式连接图查看整座工厂。

- **在线使用：** <https://seanz298.github.io/satisfactory-calculator/>
- **离线使用：** 从 [Releases](https://github.com/seanz298/satisfactory-calculator/releases) 下载 `satisfactory-calculator.html`，用 Chrome、Edge 或 Firefox 打开即可。

整个工具就是一个静态网页：不需要后端、不需要账号、不需要安装。方案保存在你的浏览器里。

## 功能

| 模块 | 可以做什么 |
| --- | --- |
| 产线规划 | 按供给正向计算、从目标产物反推，或只用一种输入限制产量；可锁定产量、选择替代配方 |
| 最优配方 | 反推模式下所有物品的全部配方一起比较，按原料消耗最少、机器最少、耗电最少或指定原料最少换成最优组合；保留一键石油 / 铝预设 |
| 工厂布局 | 类似 Axure 的画布：按真实占地摆放机器，网格吸附和对齐线、标尺、对齐 / 等距分布、组合、图层、楼层、便签和连线，导出 PNG / SVG |
| 供给清单 | 把外部供给 / 反推需求复制为文字清单，或下载 CSV |
| 机器与频率 | 机器按里程碑解锁顺序（或上下游顺序）排列；逐台频率、索莫晶体、能量碎片；一键“末台满载”，把每组末台补到满频率 |
| 副产物与流体 | 剩余物料可送 AWESOME 回收站（计入回收站座数、耗电和积分）、设为产物，或添加下游产物；流体优先封装成固体；回流环路显示循环量和最省的启动补料点 |
| 发电 | 多个独立发电目标，燃料、水、发电和核废料处理链统一配平 |
| 产线连接图 | 网络图、树状图和卡片画布，支持缩放、全屏、SVG 导出，以及在端口之间手动连线 |
| 回收点数优化 | 用内置的 HiGHS 求解器求全图最大回收点数，只使用已解锁的替代配方 |
| 地图与物流 | 交互式资源地图、采集设备、火车运力和传送带 / 管道容量检查 |
| 建设与进度 | 建材统计、已建机器跟踪、太空电梯和 HUB 里程碑物资 |
| 方案管理 | “保存”按钮和 Ctrl+S、已保存 / 未保存提示、可同时打开多个规划页（可选）、导出单个或全部方案为 JSON、导入并合并 |
| 自定义规则 | 耗电、发电量、阶段需求和配方输入消耗倍率 |

## 快速开始

1. 打开[在线版](https://seanz298.github.io/satisfactory-calculator/)，或在较新的浏览器中打开本仓库的 `index.html`。
2. 添加外部供给或资源采集点，或把模式切换为“从产物反推供给与产线”。
3. 添加最终产物，选择配方并设置目标产量。
4. 查看机器、耗电和副产物，再打开“产线图与思维导图”检查上下游连接。
5. 点“保存”（Ctrl+S / ⌘S）。用“导出 → 导出全部方案”备份。

如果不想直接打开文件，也可以在本地起一个 HTTP 服务：

```bash
python3 -m http.server 8000
```

然后访问 <http://localhost:8000>。

## 保存、导出与导入

- 方案自动保存在当前浏览器的 `localStorage` 中，不会上传到任何服务器。顶栏会显示当前方案是否已保存。
- “导出 → 导出当前方案”把一个方案存为 `方案名称.json`；“导出全部方案”把所有已保存方案、当前编辑和已有产线基准合成一个文件。
- “导入并合并”可一次选择多个 JSON 文件，追加其中的方案；重名会自动编号。任何一个文件无效，整批导入都会取消。
- 在线版、离线文件以及不同浏览器的存储互不相通，需要通过导出、导入来转移方案。
- 清除网站数据会删除已保存的方案，重要方案请保留导出的备份。
- 不提供账号、云端保存或多人实时协作。

## 优化器

**全配方最优**（反推模式，05 区）：选择目标——原料消耗最少（按全图储量加权）、机器最少、耗电最少或指定原料最少——所有物品的全部配方一起求解。目标相同时再比较另一项（原料目标比机器，其余比原料）。替代配方跟随设置中的已解锁列表，没有勾选时使用全部替代配方。新配方直接应用到当前方案，可以撤销。

**拉清单**（04 区）：复制外部物料（原料在前）的需求、当前供给和差额，以及产物、机器数和耗电；也可以下载同样内容的 CSV，用 Excel 打开。

**石油 / 铝最优配方**（反推模式，05 区）：把石油相关配方（塑料、橡胶、聚合树脂、重油残渣、燃料、石油焦、涡轮燃油）和铝相关配方（氧化铝溶液、碎铝渣、铝锭、复合铝板、铝制外壳、二氧化硅）放在一起求解。先让原油和铝土矿消耗最少，再让其他原料最少（按全图储量加权）。设置中勾选了已解锁替代配方时，只在这些配方里选择。结果可以撤销。

**回收点数优化**（设置页）：求全图最大回收点数。可选择地图纯度、频率、索莫晶体预算、预留电力、时间上限和外星电力增幅器策略，也可以用当前方案的原料供给限制采集量。计算用内置的 HiGHS WebAssembly 求解器在可取消的后台线程中完成，不需要服务器或网络。模型采用固定频率，机器台数取整、末台降频，所以结果只对这个模型最优，不等于频率连续可调时的最优解。结果先预览，再保存为一个可编辑的新方案。

## 项目结构

| 路径 | 说明 |
| --- | --- |
| `index.html` | 构建生成的单文件网页，可直接托管或离线使用 |
| `src/template.html` | 页面结构和构建插入点 |
| `src/styles.css` | 界面样式 |
| `src/app.js` | 规划、机器、电力、连接图、地图、进度、物流和方案管理 |
| `src/solver.js` | 规划使用的线性规划求解器 |
| `src/plan-files.js` | 方案文件的导出、导入与合并 |
| `src/optimizer-core.js`、`src/optimizer-ui.js` | 回收点数优化的模型与界面 |
| `src/bootstrap.js` | 内置数据解压与启动 |
| `data/` | 配方、物品、图标、地图数据、优化器数据表和翻译 |
| `vendor/highs/` | 固定版本的 HiGHS-JS WebAssembly 求解器 |
| `scripts/build.py`、`scripts/package.py` | 构建网页；把清洁源码打包到 `dist/` |
| `tests/` | 计算与文件处理测试 |

代码为原生 JavaScript、HTML 和 CSS，不使用前端框架。

## 开发

构建需要 **Python 3.8+**，只用标准库：

```bash
python3 scripts/build.py      # Windows：py -3 scripts/build.py
```

修改 `src/` 或 `data/` 后，重新构建并提交生成的 `index.html`；直接修改 `index.html` 会在下次构建时被覆盖。

测试需要 **Node.js 18+**，不需要 npm install：

```bash
for t in tests/*.cjs; do node "$t"; done
```

## GitHub Pages

在 **Settings → Pages** 中选择 **Deploy from a branch**，分支选 `main`，目录选 **/ (root)**。`index.html` 必须保留在仓库根目录。

## 当前限制

- 游戏数据为内置的 1.2.3.1 版本快照，不会自动更新。
- 计算结果是稳态物料平衡，不模拟启动时间、管道填充等瞬态过程。
- 最优解对同一物品混用两种配方时，只会采用用量最大的那一种，结果可能略高于真正的最优值。
